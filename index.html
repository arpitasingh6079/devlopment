query_negative_margin_detection.sql PostgreSQL / ANSI SQL 
WITH RegionalDiscountAggregates AS (
  SELECT 
    t.region_id,
    r.region_name,
    p.category,
    COUNT(t.transaction_id) AS total_orders,
    ROUND(AVG(t.applied_discount_rate), 4) AS avg_discount_rate,
    SUM(t.gross_revenue) AS total_gross_revenue,
    SUM(t.net_margin) AS total_net_margin
  FROM transactions t
  INNER JOIN regions r ON t.region_id = r.id
  INNER JOIN products p ON t.product_id = p.id
  WHERE t.transaction_date >= '2025-01-01'
  GROUP BY t.region_id, r.region_name, p.category
)
SELECT 
  region_name,
  category,
  total_orders,
  avg_discount_rate,
  total_gross_revenue,
  total_net_margin,
  -- Anomaly Flag: Where discount stacking caused negative unit economics
  CASE 
    WHEN total_net_margin < 0 THEN 'CRITICAL_LEAKAGE'
    WHEN avg_discount_rate > 0.25 THEN 'HIGH_DISCOUNT_RISK'
    ELSE 'HEALTHY_MARGIN'
  END AS margin_health_status
FROM RegionalDiscountAggregates
ORDER BY total_net_margin ASC;

* This query isolated 1,420 transactions in the West regional cluster where stacked promo codes produced negative unit margins.

Retail Sales & Revenue Leakage Dashboard

Tools: Power BI, SQL (PostgreSQL), Advanced Microsoft Excel

1. Business Problem & Discovery

A multi-regional retail chain observed a 14% drop in overall net margin despite a 7% year-over-year increase in top-line transaction volume. Regional managers lacked transparency into branch-level discount behaviors, resulting in undetected margin erosion from overlapping regional promo codes and unapproved sales markdown combinations.

2. Data Extraction & Cleansing (SQL & Excel)

• Deduplication: Cleaned 54,200+ raw transactional records, filtering out 1,140 cancelled or reversed transactions using SQL window functions (`ROW_NUMBER() OVER(PARTITION BY order_id)`).

• Margin Calculation Logic: Formulated custom SQL scripts calculating true Net Margin: Net_Margin = (Unit_Price * (1 - Discount_Rate) * Qty) - (COGS * Qty) - Shipping_Cost.

• Anomaly Isolation: Flagged 1,420 orders in the Western regional branch that had an effective combined discount exceeding 45%, producing negative gross margin on premium inventory items.

E-Commerce Order Fulfillment Process Optimization

Frameworks: BPMN 2.0, Gap Analysis, Root Cause (Fishbone), Jira User Stories

1. Operational Bottleneck & As-Is Audit

Order fulfillment turnaround averaged 48 hours, causing customer support tickets to surge by 31% during peak quarters. Conducting a gemba walk and workflow time-study across 3 warehouse facilities revealed three major handoff delays: manual paper-based pick list printing, disjointed address verification, and duplicate quality checks.

2. As-Is vs. To-Be Workflow Comparison

As-Is Bottlenecks (48 Hours)
  • Batched paper printing created 4.5-hour warehouse idle queues.
  • Invalid postal addresses flagged manually only at shipping label station.
  • Dual manual inspection of packed cartons caused redundant verification.
To-Be Optimization (37.4 Hours)
  • Direct digital routing to handheld Android/Zebra barcode scanners.
  • Upstream address validation API at digital checkout stage.
  • Inline weight-sensor automated verification replacing second manual check.

3. Deliverables Authored

• BPMN 2.0 Swimlane Flowcharts: Modeled interactions across Customer, ERP (SAP), Warehouse Management System (WMS), and Courier Logistics.

• 14 INVEST User Stories: Authored in Jira with Gherkin acceptance criteria (Given/When/Then) for the engineering team building the handheld scanner app.

• UAT Test Protocol: Supervised 3-day simulated pilot across 200 test shipments to validate barcode error handling and edge cases.
